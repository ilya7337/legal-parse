# Архитектура LegitFeed

## Обзор

LegitFeed — MVP аналога Whytrend: непрерывный, юридически корректный мониторинг
классифицированных открытых источников (RSS/Atom-фидов) с очисткой, объяснением
аномалий и формированием датасета для ML.

Принципы проектирования:

* **Fail-closed по умолчанию** в юридическом слое: неизвестность трактуется как
  запрет, а не разрешение.
* **Provenance everywhere**: каждая запись датасета несёт `url`, `license`,
  `license_url`, `snapshot_at`.
* **Минимизация данных (152-ФЗ)**: храним только очищенный, маскированный текст.
* **Воспроизводимость**: каждый прогон пишет JSONL-артефакты в `data/` и строку
  в `pipeline_runs`.

## Поток данных

1. `config/sources.yaml` → реестр источников (правовой статус обязателен).
2. `audit_source()` → `AuditResult`; если `allowed=False` — сбор не выполняется.
3. `FeedCollector.collect_one()` → вежливый HTTP-запрос (или фикстура) → `RawItem`.
4. `dedupe_raw()` → точная дедупликация внутри прогона.
5. `Cleaner.clean_many()` → `CleanDoc` (ПДн замаскированы, дубликаты отброшены).
6. `AnomalyDetector.detect_many()` → `AnomalyRecord` с объяснениями.
7. `build_dataset()` → разметка, сплиты, валидация, экспорт.

## Ключевые решения

* **Свой parser robots.txt вместо библиотеки**: правила RFC 9309 тестируемы
  построчно, что критично для юридических требований.
* **Свой TF-IDF вместо sklearn**: меньше зависимостей, детерминированные
  объяснения аномалий.
* **SQLite по умолчанию, PostgreSQL в проде** через `LEGITFEED_DATABASE_URL`
  (SQLAlchemy-абстракция, compose-файл прилагается).
* **Offline-режим** (`LEGITFEED_OFFLINE=true`): вся демонстрация и CI работают
  на фикстурах без сети.
